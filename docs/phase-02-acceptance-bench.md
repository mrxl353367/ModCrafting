## 首批范围与完成条件

1. 抽取无 Node/Electron 依赖的三态判定，Core 与 Desktop 共用；保留两端原动作、断言、流程和响应字段。
2. 增加版本化的统一报告摘要：来源、fixture/live、场景、版本、断言与清理证据。摘要不冒充执行证据，不把 Desktop 的未知清理状态报告为成功。
3. Fabric-Bench MVP 直接调用现有 Core 执行器，覆盖五类支持断言与缺证据、能力不足、清理失败、取消等反例。JSON 案例、实际输出、预期 verdict/code 对比可重复运行；模拟符合预期与游戏 PASS 分开统计。
4. 提供 CLI、定向回归和独立插件 CI 接入；以 Node 22/24 验证，不增加依赖、工具、版本矩阵或模型调用。
5. 报告实际结果、旧失败基线与未验证项，自动归档。

首批先完成离线 MVP。用户随后要求快速推进，已在任务专用工程、独立 gameDirectory 与 ModCrafting Test World 中补做真实基准，并补齐 Desktop 清理/快照证据。实际结果见实施报告；离线 CLI 默认行为保持，不读取普通存档或接入模型 API。P1 真实报告是历史证据，本轮结果另存。

## 最小实现顺序

检查旧调用链 → Core 公共判定/摘要 → 两端适配 → Bench 案例与 CLI → 定向回归、类型检查与受影响构建 → 交付报告。

第一批统一的是判定与报告，不宣称 Desktop 全部断言已移植，Fixture Bench 也不是跨 Agent 或真实游戏功能排行榜。
