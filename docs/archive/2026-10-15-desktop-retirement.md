# Desktop 默认入口退役与工程路径迁移

**归档日期**：2026-10-15<br>
**触发方式**：大功能自动<br>
**问题类型**：Core 数据迁移、构建入口和发布配置调整

## 背景与决定

用户要求 Desktop 后续退出，外部 Agent / IDE 承担模型、规划和编辑，Core/MCP 配合可选浏览器提供工程到游戏闭环。P2/P3 本地验证后，P4 的 Qoder 调用因无登录环境保留；用户随后明确授权开始 P5。

旧 Desktop runtime 迁移会复制并删除源目录，不能直接复用。P5 选择复用既有配置路径格式和 Core 工程检查，仅向新数据根导入路径引用；旧聊天、密钥、存档、报告和大缓存全部原地保留，无需重复 node_modules 或工具链副本。

## 改动

| 位置 | 结果 |
|---|---|
| Core desktop-migration.ts + CLI/build | 默认只读；显式新目录导入；拒绝覆盖、嵌套和路径别名；最后提交迁移记录/清单 SHA；重新检查工程 |
| MCP / browser-server / App | 同一迁移清单对 Agent 和浏览器开放，使用原有认证和工程检查；19 工具输入不变 |
| package / setup / postinstall | 默认独立产品构建/启动/测试/类型检查，自举仅 esbuild；旧 Electron 显式 desktop:* |
| product Stage / CI | 独立 CLI/指南进入完整包，旧 tag 自动发布停用，仅手动确认的 v* tag 兼容发布 |
| 文档 / 旧测试 | 功能替代与保留矩阵、新主 README、完整旧 README 留档；旧工具目录测试跟随历史文档，保留原断言 |

## 验证与边界

独立测试 Node 22/24 80/80，新路线构建和类型检查通过；旧全仓仍 21 失败、23 类型错误，与 P4 相同。仓库外迁移、MCP/浏览器读回、双尺寸截图和迁移工程真实 Gradle 离线构建通过，关闭页面后任务继续。最终分发 45 文件 SHA 校验，默认启动为 Node 浏览器服务，三宿主 SDK/config 验证不冒充原生账户验收。

本轮未启动游戏、未迁移个人配置、未清理旧源码/数据、未提交或推送。原 main/9 项用户未跟踪文件保持；共享 pnpm Store，独立 node_modules，正式锁与 .npmrc 不变。已完成职责和默认入口退役，兼容源码物理剥离与 Qoder 调用保留独立边界。完整证据见 [P5 报告](../phase-05-retirement-report.md)。
