---
name: fabric-mod-development
description: Develop, inspect, scaffold, build, and diagnose Fabric 1.21.4 mods with ModCrafting's local MCP tools.
---

Use this skill for a Fabric 1.21.4 mod project on Windows.

1. Start with `modcrafting_environment_status` and `fabric_project_inspect`.
2. Before registering a block, item, entity, enchantment, or recipe, call `minecraft_data_lookup` for every vanilla ID and property used. Do not invent IDs or hardness, resistance, stack-size, or enchantment data from memory.
3. Use `fabric_docs_search` for Fabric APIs and `mc_wiki_search` for game concepts.
4. Make narrow edits with the host Agent's normal file tools, then call `fabric_validate` and start `fabric_build_start(task="build")`.
5. Poll with `fabric_job_status`; interpret failures from Gradle output before attempting another edit.

The plugin does not install a JDK. Require system JDK 21 on PATH and JAVA_HOME. MCP scaffolding includes the pinned Windows Gradle Wrapper; existing projects must provide gradlew.bat. Executing the Wrapper may download the pinned Gradle distribution and dependencies.

For visual recipes, obtain browserUrl from modcrafting_environment_status when using --web. The browser and fabric_recipe_workspace share the same project files. Use action catalog/list/read/save. Before updating, read and pass the exact revision as expectedRevision; use null only for a new ID. On RECIPE_CONFLICT, read and compare instead of blindly overwriting. Five vanilla serializers are editable: shaped, shapeless, smelting, blasting, stonecutting. Unsupported serializers or ingredient forms remain read-only. Saving requires rebuild/restart or explicit game reload before testing. Avoid ambiguous inputs matching vanilla recipes and verify the actual output in game.

For visual content parameters, use fabric_content_workspace list/read/preview/save and the same browser project. Supported declarative types are item, food, block, entity, tool and armor. Read the document; preview with its expectedRevision (null for a new ID), review changed files, then save with the returned previewRevision and the same expectedRevision. A conflict requires read/compare; never bypass it. Handwritten or externally modified generated Java is read-only. Custom textures must reference an existing project PNG; vanilla previews use an optional local cache and may show a labeled type illustration. Entities reuse pig/zombie appearance and AI. Sword mining rules and armor appearance follow vanilla types/materials. Rebuild and restart before validating Java changes. Observer capability revision 5 exposes food/block/entity parameters and integrated-server equipment attributes; client attack/knockback attributes may lag. Validate actual effects and cleanup, not only command dispatch or generated source.

For MC UI creation, use fabric_gui_workspace template/list/read/preview/save and the MC interface editor in browserUrl. template returns a data-only layout and supported component defaults; it does not write files. Supported layouts are custom-screen, option-list and hud-overlay. Use stable unique IDs, GUI-pixel coordinates, native button/toggle/slider controls and labels/panels/display slots. Labels may bind to local control values or player health/food. Buttons only close, reset defaults or increment a chosen slider; no arbitrary scripts or commands. Display slots are not server containers. Read the current revision; preview generated files with expectedRevision, then save with both expectedRevision and previewRevision. Conflicts preserve drafts; external Java is read-only. Rebuild/restart, press the configured key in game, validate actual widget messages/geometry and persisted configuration. Screen closes via its close button or normal Esc; HUD key toggles visibility. Browser interaction only simulates state. HUD trace assertions remain INCONCLUSIVE in the existing engine; report fresh native draw observations/screenshots separately, never as an automatic HUD PASS.
